# `.orchestrator-state.json`

Loaded by `epic-orchestrator`'s Claim, Spawn and Settle. The recovery table at the
end is for a human who lost track of a run.

**A ledger, never an input.** Nothing routes on it; every marker block, verdict and
checkbox is re-read from GitHub each pass. Sole exception: `progress`, which Guard's
caps read — they escalate, they never route. Gitignored; never committed. Dry-run
writes nothing.

Location: the root of the working tree the run occupies.

```json
{
  "run_id": "orch-20260903T142530Z-a4f1",
  "task_id": null,
  "issue": 360,
  "level": "normal",
  "state": "running",
  "sections": {
    "DOC-1": { "state": "done", "pr": "https://github.com/wadvanced/aurora_uix/pull/361" },
    "PAR-1":  { "state": "in_progress", "step": "review-issue", "task_id": null, "worktree": ".claude/worktrees/section-360-par-1" },
    "UI-1":  { "state": "waiting_on_deps" }
  },
  "progress": { "loop_tally": { "PAR-1": 1 }, "fingerprint": "9f2c…" },
  "waves": 3,
  "last_transition": "PAR-1: code-issue -> review-issue",
  "last_updated": "2026-09-03T14:31:02Z"
}
```

| Field | Rule |
|---|---|
| `run_id` | `orch-<UTC ISO8601 basic>-<4 hex>`, generated by Claim |
| `task_id` | always `null` here; `orchestrate-issue` patches it. Never guess it |
| `level` | this pass's `M.obs.level` |
| `state` | `running` (Claim, Settle) \| `wave_done` \| `awaiting_decision` \| `spec_pending` \| `blocked` \| `plan_pending` \| `done` (Settle). No other step sets it |
| `sections` | one entry per Section Map row: `waiting_on_deps` \| `in_progress` (+ `step`, `worktree`) \| `blocked` \| `in_review` \| `done` (+ `pr`). `worktree` is written, never read |
| `progress` | `loop_tally` (`STATUS: LOOP` verdicts and `STATUS: CHECKPOINT` results per section this run) and `fingerprint` (Guard's digest of the last settled pass). Absent on a fresh run; otherwise carried verbatim on every write |
| `waves` | integer: `wave_done` states written under this `run_id`. `0` on a new `run_id`; carried on every write; Settle adds 1 when it writes `wave_done` |
| `last_transition` | one line, e.g. `PAR-1: merged #362` |
| `last_updated` | UTC ISO 8601, refreshed on every write |

Write — always whole-file, always atomic:

```bash
tmp=$(mktemp) && cat > "$tmp" <<'JSON'
<the object>
JSON
mv -f "$tmp" .orchestrator-state.json
```

## Recovery — reading a state file you found

| `state` | `last_updated` | Reading |
|---|---|---|
| `running` | under 30 min | Live. Do not launch a second orchestrator — wait. `SendMessage` to `task_id` works only during the run's first wave; it is not re-patched after a `WAVE_DONE` re-spawn. |
| `running` | over 30 min | Probably dead. Safe to re-launch. |
| `wave_done` | any | Waiting on no one. `orchestrate-issue` re-spawns at once; after a crash between the two, plain `/orchestrate-issue <n>`. `progress` is kept. |
| `awaiting_decision` | any | Waiting on the user — a cap, a take-over question, or the review pause. Re-launch once the human event has happened. |
| `spec_pending` | any | Waiting on `orchestrate-issue`'s spec loop — approval, and the spec PR merging into `main` (`spec-pr-open`, `spec-pr-checks-pending`). Re-launch once the spec is merged; an open `spec/<n>-enriched-spec` PR is not stored yet. |
| `blocked` / `plan_pending` | any | Terminal. Read `last_transition`, fix it, re-launch. |
| `done` | any | Finished. `sections` carries the PR URLs. |
| *(no file)* | — | No run started here, or it was a `--dry-run`. |

**Re-launching is always safe** — every routing decision is re-derived from the issue.
**Never reconstruct a run from the file**; use it to identify the run.
