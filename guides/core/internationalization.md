# Internationalization (i18n)

Aurora UIX translates its strings with Gettext. The labels, error messages and UI strings the
library renders pass through a configurable Gettext backend.

The default backend, `Aurora.Uix.GettextBackend`, returns the English source strings. It reads
translation files from the `aurora_uix` dependency only, **not from your application**. To
translate the UI, [point the library at your own backend](#translating-into-your-languages).

## How it works

The library modules use `Aurora.Uix.GettextResolver`, a thin `__using__` macro that wires the
configured backend into the calling module. Your own components can use it too:

```elixir
defmodule MyAppWeb.SomeComponent do
  use Aurora.Uix.GettextResolver   # Gettext macros for the configured backend, and dt/1
end
```

At translation time Gettext looks up the locale and domain in the backend's compiled `.po` files.
When no translation is found, it calls the backend's `handle_missing_*` callbacks. The default
backend uses them to:

1. Optionally emit a `Logger.warning` so missing strings are visible during development.
2. Optionally write a stub entry to the matching `.pot` file so translators have a template.
3. Return the English source string, so the UI never shows an empty field.

## Translating into your languages

Configure your application's backend, the one `mix phx.new` generates:

```elixir
# config/config.exs
config :aurora_uix, gettext_backend: MyAppWeb.Gettext
```

The library reads this setting when it compiles; Mix recompiles it after the change. Translations
then come from your `priv/gettext/<locale>/LC_MESSAGES/` files, in the domain described below.
Error messages use the `errors` domain.

`mix gettext.extract` does not find most library strings, because they are looked up at runtime.
Collect them with the default backend, as described under
[Collecting the strings](#collecting-the-strings).

## Configuration

### Recommended: set a Gettext domain

It is strongly recommended to set `:gettext_domain` so that Aurora UIX strings are stored in their
own Gettext domain, separate from your application's default domain. Without this, running
`mix gettext.merge` can intermix or overwrite Aurora UIX translations with your own strings.

```elixir
# config/config.exs
config :aurora_uix, gettext_domain: "aurora_uix"
```

This setting takes effect at **compile time**. It sets the domain of the library strings,
including the form labels, so they are looked up in `aurora_uix.po` rather than in the default
`default.po`.

### Development settings

These keys are read by `Aurora.Uix.GettextBackend` only. They have **no effect** with another
backend.

```elixir
# config/dev.exs
config :aurora_uix,
  # Write missing-translation stubs to .pot files at runtime.
  gettext_pot_path: "priv/gettext",
  # Emit Logger.warning for every missing translation (off by default).
  gettext_show_warnings?: true
```

| Key | Type | Default | Read | Description |
|---|---|---|---|---|
| `:gettext_pot_path` | `String.t() \| nil` | `nil` | at runtime | Existing directory where `.pot` files are written. When `nil` or omitted, no file I/O occurs. |
| `:gettext_show_warnings?` | `boolean()` | `false` | at compile time | Emit `Logger.warning` for missing translations. |

For production, omit both keys.

### Custom backend

Any Gettext backend can replace the default one. A backend other than
`Aurora.Uix.GettextBackend` writes no `.pot` files and emits no warnings unless it implements that
itself.

```elixir
config :aurora_uix, gettext_backend: MyApp.CustomGettextBackend
```

A module of yours can name a backend with the `:backend` option, which applies only while
`:gettext_backend` is not configured; the application setting takes precedence:

```elixir
use Aurora.Uix.GettextResolver, backend: MyApp.CustomGettextBackend
```

**Example — a strict backend for CI that raises on any missing translation:**

```elixir
defmodule MyApp.StrictGettextBackend do
  use Gettext.Backend, otp_app: :my_app

  @impl true
  def handle_missing_translation(_locale, _domain, _msgctxt, msgid, _bindings) do
    raise "Missing translation for: #{msgid}"
  end

  @impl true
  def handle_missing_plural_translation(_locale, _domain, _msgctxt, msgid, _msgid_plural, _n, _bindings) do
    raise "Missing plural translation for: #{msgid}"
  end

  @impl true
  def handle_missing_bindings(exception, _incomplete) do
    raise exception
  end
end
```

Use it in CI only. In development and production prefer a backend that degrades gracefully.

## Collecting the strings

With the default backend and `gettext_pot_path` set, a stub is appended to the `.pot` file of the
domain the first time a missing translation is met at runtime. Run the dev server and exercise the
UI to collect the strings.

The generated stubs follow the standard `.pot` format:

```po
# Generated by Aurora Uix

msgid "First name"
msgstr ""

msgid "Items"
msgid_plural "Items"
msgstr[0] ""
msgstr[1] ""
```

An `msgid` already in the file is not appended again.

## Translation workflow

1. With `:gettext_backend` **not** configured, set `gettext_domain` and, in `config/dev.exs`,
   `gettext_pot_path: "priv/gettext"`.
2. Create the directory, start the dev server and browse the generated UI.
3. Run `mix gettext.merge priv/gettext --locale <locale>` to bring the stubs into your `.po`
   files, and fill in the `msgstr` values.
4. Configure `gettext_backend: MyAppWeb.Gettext` and restart the server.

See the [Gettext merge documentation](https://hexdocs.pm/gettext/Mix.Tasks.Gettext.Merge.html)
for the merge options.

## Locale selection

Aurora UIX does not manage the active locale: that is the responsibility of the host application.
Gettext keeps the locale per process, so set it both for the HTTP request, in a plug, and for the
LiveView process, in an `on_mount` hook:

```elixir
# In the router
plug :put_locale

defp put_locale(conn, _opts) do
  Gettext.put_locale(get_session(conn, :locale) || "en")
  conn
end
```

```elixir
defmodule MyAppWeb.LocaleHook do
  def on_mount(:default, _params, session, socket) do
    Gettext.put_locale(session["locale"] || "en")
    {:cont, socket}
  end
end
```

```elixir
# In the router, around the Aurora UIX routes
live_session :localized, on_mount: MyAppWeb.LocaleHook do
  auix_live_resources("/products", MyAppWeb.ProductViews.Product)
end
```
