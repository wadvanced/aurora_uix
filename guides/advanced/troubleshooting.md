# Troubleshooting

Common issues and solutions for Aurora UIX.

## Dependency Resolution Fails

**Symptoms:** `mix deps.get` reports that version solving failed, naming `phoenix_live_view`.

**Solution:** Aurora UIX needs `phoenix_live_view ~> 1.2`. Raise that requirement in your `mix.exs`.

## Styling Not Applied

**Symptoms:** Aurora UIX components render but styling appears broken or missing, or the CSS build
fails.

**Solutions:**

1. **Basic setup checks:**
   - Ensure you've run `mix auix.gen.stylesheet` to generate the stylesheet
   - Verify `assets/css/app.css` imports `./auix-variables.css` and then `./auix-rules.css`
     (see [CSS Configuration](../introduction/getting_started.md#css-configuration))
   - `Can't resolve 'auix-variables.css'` means an import lacks `./`. If it comes from
     `auix-stylesheet.css`, an earlier version generated it: re-run `mix auix.gen.stylesheet`
   - Rebuild the assets: `mix assets.build`
   - In development, restart your server to ensure hot reload picks up CSS changes

2. **Theme configuration issues:**
   - Check your theme is correctly configured in `config/{environment}.exs`:
     ```elixir
     config :aurora_uix, theme_name: :white_charcoal
     ```
   - The built-in themes are `:white_charcoal`, `:vitreous_marble` and `:blue_graphite`
   - Run `mix auix.gen.stylesheet` again after changing the theme configuration

3. **Custom theme CSS issues:**
   - If using a custom theme module, verify it implements the `Aurora.Uix.Templates.Theme` behaviour
   - Ensure all CSS rules in your custom theme are valid CSS (check for syntax errors)
   - Verify the theme module uses the correct macro: `use Aurora.Uix.Templates.Theme, theme_name: :your_theme_name`
   - Test CSS rules individually by inspecting with browser DevTools
   - Check theme module is properly compiled: `mix compile --force`

## Info Message Without Text

**Symptoms:** The message after a save is a solid block with no readable text.

**Cause:** Your `assets/css/auix-bridge-daisyui.css` was copied by Aurora UIX 0.2.0 or earlier, and
gives the info message one colour for text and background. `mix auix.gen.stylesheet` keeps a bridge
file you already have.

**Solution:** In that file, set `--auix-color-info-text: var(--color-info-content);`. If you have not
edited the file, `mix auix.gen.stylesheet --force` replaces it with the current one.

## Icons Not Displaying

**Symptoms:** Icons appear as blank spaces or missing symbols.

**Solutions:**
- If your application uses Heroicons, as a new Phoenix application does, verify `app.css` has
  `@source "../../deps/aurora_uix/priv/static/classes.js";`
- Otherwise verify it imports `./auix-icons.css`, generated by `mix auix.gen.icons`
- `mix auix.gen.icons` stops with `The heroicons dependency was not found` when your application
  does not have it: add the `heroicons` dependency, as in
  [Icons Configuration](../introduction/getting_started.md#icons-configuration)
- Check the browser DevTools (Inspect Element) to see if the icon element has the correct CSS class applied

## UI Components Not Rendering

**Symptoms:** Pages show blank or malformed UI elements.

**Solutions:**
- Verify you've defined resource metadata with `auix_resource_metadata` macro
- Ensure the layout DSL in `auix_create_ui` includes the fields you want to display
- Check for errors in the browser console (F12 / DevTools)
- Verify LiveView is properly connected (check for `PhxLiveSocket` connection in console)

## Compilation Errors

**Symptoms:** `mix compile` fails with module or macro errors.

**Solutions:**
- Ensure all dependencies are installed: `mix deps.get`
- Check that your resource and layout macros follow the correct syntax
- Verify all schema modules are correctly imported in your metadata module
- Clear build artifacts and recompile: `mix clean && mix compile`

## LiveView Connection Issues

**Symptoms:** UI updates don't work, no response to form submissions.

**Solutions:**
- Verify your router includes the necessary LiveView routes
- Check that Phoenix LiveView is properly installed and configured
- Open browser DevTools to see if there are WebSocket connection errors
- Ensure the `/live` endpoint is accessible (check router configuration)

## Incorrect LiveView Routes

**Symptoms:** "module not found" errors, a `FunctionClauseError` in `auix_apply_action` when a page is
opened, or pages that show the wrong view.

**Cause:** `auix_create_ui` generates, for each resource, these modules:

```text
MyAppWeb.ProductViews.Product.Index            # the LiveView: the only module to route to
MyAppWeb.ProductViews.Product.IndexComponent   # LiveComponents, rendered by a LiveView
MyAppWeb.ProductViews.Product.FormComponent
MyAppWeb.ProductViews.Product.ShowComponent
```

There is no `Show` LiveView: the `Index` LiveView shows a record, and the action of the route
selects the view.

**Solutions:**

1. **Use the `auix_live_resources` helper (recommended):**
   ```elixir
   import Aurora.Uix.RouteHelper

   scope "/", MyAppWeb do
     pipe_through :browser
     auix_live_resources "/products", ProductViews.Product
   end
   ```

2. **If you write the routes yourself, give each one its action:**
   ```elixir
   live "/products", ProductViews.Product.Index, :index
   live "/products/new", ProductViews.Product.Index, :new
   live "/products/:id/edit", ProductViews.Product.Index, :edit
   live "/products/:id/show", ProductViews.Product.Index, :show
   live "/products/:id/show-edit", ProductViews.Product.Index, :show_edit
   ```
   A route without an action, such as `live "/products", ProductViews.Product.Index`, raises a
   `FunctionClauseError`.

3. **Verify routes with `mix phx.routes`:**
   Run this command to see all registered routes and verify they point to the correct modules:
   ```shell
   mix phx.routes | grep products
   ```
   Look for routes like: `GET  /products   MyAppWeb.ProductViews.Product.Index :index`

## Database Issues

**Symptoms:** Errors loading or saving data, missing table errors.

**Solutions:**
- Verify PostgreSQL (or your database) is running
- Check that the correct database is configured in your `config/`
- Run pending migrations: `mix ecto.migrate`
- Verify your schema module matches the actual database table structure

## Embedded and Associated Resources Metadata

**Symptoms:** Field options declared for an embedded record, or for the entries of an
association, are ignored.

**Cause:** The field is rendered with another resource than the one that holds the options.

- An embedded field uses the resource named `<parent>__<field>` (`:post__comment` for the `comment`
  field of `:post`), unless the field names one with `resource:`.
- An association uses the latest resource declared for the related schema, unless the field names
  one with `resource:`.

**Solution:** Name the resource on the field:

```elixir
auix_resource_metadata :post do
  ash_resource Post
  field :comment, resource: :comment_form
end

auix_resource_metadata :comment_form do
  ash_resource Comment
  field :description, html_type: :textarea
end
```

A resource declared as `:post__comment` is used without `resource:`.

**Compilation fails after adding `resource:`:**

- `links to the unknown resource`: the name matches no resource of the module, declared or
  imported.
- `whose schema is ...; the field relates to ...`: the named resource describes another schema
  than the one the field relates to.
- `only an embedded field or an association links to a resource`: the field is a plain column. On
  the foreign-key column of a many-to-one, put `resource:` on the association field.
- ``requires the `:context` option``: the resource is declared on an Ecto schema that has a table.
  Give `context:` with its CRUD functions, or remove the declaration to use the resource the
  library creates.

## Ash Policy-Protected Resource Shows No Rows

**Symptoms:** The generated index for an Ash resource is empty, even though the
data exists in the database. No error in the logs.

**Cause:** The resource is guarded by `Ash.Policy.Authorizer` with a policy
that requires an actor (e.g. `authorize_if actor_present()`), but Aurora UIX is
not forwarding one. Reads quietly translate `Ash.Error.Forbidden` to an empty
result so the LiveView stays alive.

**Solution:** Tell Aurora UIX which `socket.assigns` key holds the actor:

```elixir
auix_resource_metadata :template,
  ash_resource: MyApp.Templates.InterfaceDocumentTemplate,
  backend_opts: [ash_actor_assign: :current_user]
```

Also confirm the assign is actually set — typically via an `on_mount` hook
inside a `live_session`. See
[Ash Integration → Authorization and policies](../core/ash_integration.md#authorization-and-policies).

## Ash Write Is Forbidden

**Symptoms:** Submitting a generated form for an Ash resource shows an error flash about a forbidden
action, or deleting a row from the index shows "Item could not be deleted".

**Cause:** The policy refused the write, most often because the actor is missing. Reads turn a
refusal into an empty result; writes cannot.

**Solution:** Set `backend_opts: [ash_actor_assign: …]` on the resource metadata, and make sure
the assign is on the socket before the view mounts. A user whose policies forbid deleting should not
be offered the action; see
[Custom Actions](../customization/custom_actions.md) to remove it.

## Performance Issues

**Symptoms:** Slow page loads or unresponsive UI.

**Solutions:**
- Check for N+1 query problems in your context functions
- Use Phoenix DevTools or `:observer` to identify bottlenecks
- Verify preloads are configured for associations in your queries
- Consider pagination for large data lists
