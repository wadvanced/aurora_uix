# What's New in 0.2.1

0.2.1 has three compile-time changes that can stop a module from compiling; see
[Upgrading from 0.2.0](#upgrading-from-0-2-0). Coming from a version earlier than 0.2.0? Follow
[Upgrading from 0.1.7](0.2.0.md#upgrading-from-0-1-7) first. The [CHANGELOG](../../CHANGELOG.md) keeps the
complete history.

## Heads-up: refreshed look and CSS overrides

0.2.1 refreshes the look of every theme: inputs, buttons, groups, embedded records, sections, modals, the
index table, cards and menus take a new frame, and `:blue_graphite` joins the built-in themes. Nothing fails
to compile, but a host that overrides Aurora UIX styling may find its overrides no longer match. Check
these:

- **Regenerate the stylesheet.** Run `mix auix.gen.stylesheet`. `auix-variables.css` and `auix-rules.css`
  are build artifacts, so without it the new `--auix-*` variables and `.auix-*` rules are missing from your
  CSS and components lose styling silently. See the [Styling](../customization/styling.md) guide.
- **Host-owned files are not regenerated.** `auix-custom.css` and `auix-bridge-*.css` are skipped on later
  runs, so review them by hand. Use `--force` only after saving your own edits: it replaces them with the
  current defaults.
- **Variables whose default changed.** If you override one of these, check that your value still suits the
  new frame:
  - Sizes: `--auix-items-card-label-width` (now `8rem`), `--auix-font-size-title` (now `1.25rem`) and
    `--auix-font-size-group-title` (now `0.875rem`).
  - Focus: `--auix-color-input-border-focus`, `--auix-color-textarea-border-focus`,
    `--auix-color-select-border-focus` now follow `--auix-color-focus-ring` instead of
    `--auix-color-border-focus`. `--auix-color-pagination-current-border` now follows
    `--auix-color-pagination-current-bg`.
  - Buttons: `--auix-color-button-alt-text`, `--auix-color-button-alt-border`,
    `--auix-color-button-alt-bg` and `--auix-color-button-iconized-bg-hover`.
  - Index table: `--auix-color-items-table-header-text` and `--auix-color-items-table-body-text`.
  - Sections and groups: the `--auix-color-sections-tab-*`, `--auix-color-sections-content-border` and
    `--auix-color-group-container-*` variables.
  - Checkbox label: `--auix-color-checkbox-label-text`.
  - White Charcoal errors: `--auix-color-error` (input error border, now rose-500 `#F43F5E`) and
    `--auix-color-error-text-default` (inline error text, now rose-700 `#BE123C`).
- **New variables.** Sizes (`--auix-control-height`, `--auix-padding-control`, `--auix-focus-ring-width` and
  others), success, warning and selection colors, and `--auix-color-focus-ring-halo`. A custom theme
  module should define the colors; the [Theming](../customization/theming.md) guide lists them.
- **Class overrides.** `auix-button--danger`, `auix-flash--success` and `auix-flash--warning` are new, and
  the `auix-items-card-*` classes changed. A rule that targets the old structure of an input, button, group,
  section, modal, table or card may need new selectors; the
  [Class reference](../customization/styling.md#class-reference) lists each class and the variables it
  reads.
- **Theme CSS sanitizer.** Theme rules may now set `resize` (`none`, `block`, `both`, `vertical`,
  `horizontal`, `inline`) and `content` (one plain quoted string such as `""`). Any other value of either
  property is still dropped.

## Reusable components

`auix_create_ui` now generates an `IndexComponent` next to `FormComponent` and `ShowComponent`, and the three
can be embedded in a LiveView you write:

```elixir
<.live_component
  module={MyAppWeb.ProductViews.Product.IndexComponent}
  id="low-stock"
  where={[{:quantity_at_hand, :lt, 10}]}
/>
```

- The generated `Index` LiveView keeps its list, routes, handler hooks and modal.
- `generate:` on `auix_create_ui` chooses the kinds of module; leave out `:index_live` to get the components
  alone.
- A component never navigates. It tells its parent what the user asked for, and the parent decides.
  `Aurora.Uix.Navigation` holds the navigation state of the generated LiveView.
- Every generated module has a name: `module_name:` and `index_live` set it, `use:` takes a component
  generated in another module. A LiveView you write declares the same pairing and gives the component its
  `resource`.
- `on_mount Aurora.Uix.Live.ComponentHooks` keeps embedded components up to date with `Aurora.Uix.Events`.
- A one-to-many list is an embedded `IndexComponent`.

The [Reusable Components](../core/components.md) guide has the contract and the examples.

## Upgrading from 0.2.0

Five cases need a change:

- A views module with two resources on one schema no longer compiles: their generated modules had the same
  names, and one silently replaced the other. Give one resource `module_name:` on its layouts, `use:` and an
  `index_live` line; see
  [Naming and reusing generated modules](../core/components.md#naming-and-reusing-generated-modules).
- A resource on an embedded-only schema generates no modules, whatever its name: an Ash resource
  with `data_layer: :embedded`, an Ecto schema declared with `embedded_schema`, and the inline
  schema of `embeds_one` and `embeds_many`. The resource the library creates for an embedded field
  (`<parent>__<field>`) generates none either. Remove any reference to
  `<Module>.<EmbeddedSchema>.Index`, `.FormComponent` and `.ShowComponent`, and their routes.
- `resource:` on a field now takes effect. An embedded field or an association with `resource:` is
  rendered with the named resource; in 0.2.0 the option was accepted and the field kept its default
  resource. A name that matches no resource, a resource that describes another schema, and
  `resource:` on a field that is neither embedded nor an association no longer compile. On the
  foreign-key column of a many-to-one, move `resource:` to the association field.
- A custom fields parser defines `embedded_schema?/1`, returning `true` for a schema that exists
  only embedded in another one. Without it the views module does not compile.
- An Ash embeds-one field with no value now renders its blank inputs, and the form submits them: the
  embedded resource's `create` action and validations run on save. In 0.2.0 the field rendered nothing and
  the attribute stayed `nil`. If the embedded resource requires fields, saving with the embed left blank
  fails with its errors (for example `first_name: must be present`). Fill in the embed, or check that the
  records reaching the form, test fixtures included, carry the values your domain guarantees. If the field
  must not be edited on that screen, leave it out of the layout.

`@auix.uri_path`, `@auix.uri_path_id`, `@auix.routing_stack` and `@auix[:index_new_link]` stay readable; a
handler that assigned one of them directly now changes navigation with `auix_route_forward/2` and
`auix_route_back/1`.

In a LiveView test, the redirect after a form save and after a form close now comes from the generated
`Index` LiveView, one message after the form event. Replace `render_submit() |> follow_redirect(conn)`
with `render_submit()` followed by `assert_redirect(view)`. Nothing changes in the browser.

Coming from a version earlier than 0.2.0? Follow [Upgrading from 0.1.7](0.2.0.md#upgrading-from-0-1-7) first.
