# What's New in 0.2.0

This release moves Aurora UIX's DSLs to [Spark](https://hexdocs.pm/spark). Every option is now
validated at compile time: an unknown or mistyped option fails compilation with the line that
declares it, instead of being silently ignored. The [CHANGELOG](../../CHANGELOG.md) keeps the
complete history.

- [Upgrading from 0.1.7](#upgrading-from-0-1-7)
  - [Resource metadata](#resource-metadata)
  - [Layouts](#layouts)

## Upgrading from 0.1.7

### Resource metadata

**1. Options and a `do` block don't mix.** Keyword options alone still work. When the
resource also configures fields, move its options into the block as calls:

```elixir
# Before
auix_resource_metadata :product, context: Inventory, schema: Product do
  field :name, required: true
end

# After
auix_resource_metadata :product do
  context Inventory
  schema Product
  field :name, required: true
end

# Unchanged: options without a block
auix_resource_metadata :category, context: Inventory, schema: Category
```

**2. Backend options go under `backend_opts`.** This covers Ash's `ash_actor_assign` /
`actor_assign` and action names, and a context's CRUD function overrides
(`list_function`, `list_function_paginated`, `get_function`, `create_function`, ...):

```elixir
# Before
auix_resource_metadata :post, ash_resource: Post, ash_actor_assign: :current_user

# After
auix_resource_metadata :post, ash_resource: Post, backend_opts: [ash_actor_assign: :current_user]
```

They are validated by the resource's backend, so an Ash option on an Ecto resource fails
compilation.

**3. A field's `order_by` and `where` go under `query_opts`:**

```elixir
# Before
field :category_id, option_label: :name, order_by: [desc: :name], where: [{:active, true}]

# After
field :category_id, option_label: :name,
  query_opts: [order_by: [desc: :name], where: [{:active, true}]]
```

**4. Renderer settings go under `renderer_opts`:**

```elixir
# Before
field :cost, renderer: :rating, data: %{max: 10}

# After
field :cost, renderer: :rating, renderer_opts: [max: 10]
```

**5. Uploads are an `upload` block:**

```elixir
# Before
field :image, data: %{upload: %{allow: [accept: ~w(.png)], consume: &MyApp.store/1}}

# After
field :image do
  upload allow: [accept: ~w(.png)], consume: &MyApp.store/1
end
```

**6. `data` only accepts `select`.** The rest of `data` is filled by the backend parser. To
replace a select's choices: `data: %{select: %{opts: [Active: "active", Archived: "archived"]}}`.

**7. Options that were silently ignored now fail.** For example `max_length:` was never a
field option; use `length:`. A context resource without `context` also fails compilation.

**8. A module can hold only one Spark DSL.** An Ash domain (`use Ash.Domain`) or resource can't
also `use Aurora.Uix`; declare the UI in a separate module.

### Layouts

The layout DSL is unchanged. What it produces is now typed (see
[Layout Structures](../advanced/advanced_usage.md#layout-structures)):

**1. Custom renderers and templates read layout nodes.** `@auix.layout_tree` is an
`Aurora.Uix.Layout.Node` struct instead of `%Aurora.Uix.TreePath{}`. Match on the struct
instead of `tag`, and read its keys instead of `name`, `config`, `opts` and `inner_elements`:

```elixir
# Before
def render(%{auix: %{layout_tree: %{tag: :group, config: config}}} = assigns), do: ...
# config[:title], layout_tree.inner_elements

# After
def render(%{auix: %{layout_tree: %Aurora.Uix.Layout.Node.Group{title: title}}} = assigns), do: ...
# layout_tree.children
```

A field node holds its resolved `%Aurora.Uix.Field{}` in `field`. A layout's options are in
`options`, and its `*_action` entries are in `actions`. A template's `generate_module/1` reads the
layout type from `parsed_opts.layout_type`.

**2. `@auix_layout_trees` is gone.** Declare layouts with `auix_create_ui`; writing
`%TreePath{}` structs by hand is no longer supported. The generated `auix_layout_trees/0` is
now `auix_layouts/0`.

**3. Group and section ids follow their position.** They used to embed the compile time, for
example `auix-group-quantities-1a2b3c4d123`; now they look like `auix-group-quantities-product-form-0`.
Update any CSS or JavaScript that matched the old ids.

**4. Layouts are validated.** `auix_create_ui`, `auix_create_layout` and every layout are now part
of the Spark DSL (`Aurora.Uix.Layout.CreateUI`). These used to be ignored or merged and now fail
compilation at their line:

- an unknown layout option (for example `or_where:` or `select:` on `index_columns`) or field
  option;
- a layout for a resource the module does not declare, or a field the resource does not have;
- two layouts of the same type for one resource in one `auix_create_ui` (they used to merge):
  declare it once;
- a `section` outside `sections`, or a second `auix_create_ui` in a module.

**5. A field list made only of `key: options` pairs is read as options.** Spark reads such a
list as the sub-layout's own options. Write those fields with the new `field`, or add a plain
field to the list:

```elixir
# Before
inline [id: [hidden: true], reference: [readonly: true]]

# After
inline do
  field :id, hidden: true
  field :reference, readonly: true
end

# Also fine: the list holds a plain field
inline [:name, reference: [readonly: true]]
```

The same holds for a list made only of association paths (`inline [{:category_id, :name}]`):
write each as `field {:category_id, :name}`, or add a plain field. `edit_layout` and `show_layout` with options and
no block fail the same way; add the block.

**6. `auix_create_ui` takes only `for`, `renderers` and `default_fields_layout`.** Name, title and
backend function overrides belong to `auix_resource_metadata`. Without a block, `for:` is not
accepted: write `auix_create_ui for: :product do end`.

**7. `@auix_layout_opts` is no longer read.** Pass the options to `auix_create_ui`.
