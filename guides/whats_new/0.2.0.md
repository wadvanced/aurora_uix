# What's New in 0.2.0

**This release has breaking changes.** It adds no features over 0.1.7: it moves Aurora UIX's DSLs to [Spark](https://hexdocs.pm/spark). Every option is now
validated at compile time: an unknown or mistyped option fails compilation with the line that
declares it, instead of being silently ignored. The [CHANGELOG](../../CHANGELOG.md) keeps the
complete history.

## Upgrading from 0.1.7

> #### Breaking changes {: .warning}
>
> 0.2.0 is not a drop-in upgrade. Expect to touch every module that declares
> `auix_resource_metadata`, `auix_create_ui` or a theme:
>
> - Resource options and a `do` block no longer mix; backend, query and renderer options moved
>   under `backend_opts`, `query_opts` and `renderer_opts`, and uploads are an `upload` block.
> - Options that 0.1.7 silently ignored now fail compilation.
> - `auix_create_ui` and `auix_create_layout` accept fewer options; `@auix_layout_opts` and
>   `@auix_layout_trees` are no longer read; `Layout.Blueprint`, `Layout.CreateLayout` and
>   `TreePath` are removed.
> - Themes declare rules with `rule` and `include`.
> - Custom renderers and templates read layout nodes, and `%Field{}` / `%Resource{}` have new keys
>   (`data` and `opts` shrank or are gone).
> - A module can hold only one Spark DSL, and `use Aurora.Uix.Layout.ResourceMetadata` is removed.

0. To migrate with a coding assistant, copy the [Migration prompt](#migration-prompt) and paste
   it into your assistant at the root of your project. Otherwise follow steps 1 to 3.
1. Update the dependency and run `mix compile`. Each declaration still in the 0.1.7 form fails
   at its line, and the message lists the valid options. Fix each one with
   [Resource metadata](#resource-metadata), [Layouts](#layouts) and [Themes](#themes).
2. If you wrote your own renderers, templates or layout structures, update them with
   [Custom renderers and templates](#custom-renderers-and-templates). They read structures
   whose keys changed, and not every change fails compilation.
3. Run your tests and look at your screens. A field that 0.1.7 silently ignored now applies,
   and a misspelled one is now rejected. Either can change what a screen shows.

### Resource metadata

**1. Options and a `do` block don't mix.** Keyword options alone still work. When the
resource also configures fields, move its options into the block as calls:

```elixir
# Before
auix_resource_metadata :product, context: Inventory, schema: Product do
  field :name, required: true
end

# After
auix_resource_metadata :product do
  context Inventory
  schema Product
  field :name, required: true
end

# Unchanged: options without a block
auix_resource_metadata :category, context: Inventory, schema: Category
```

**2. Backend options go under `backend_opts`.** This covers Ash's `ash_actor_assign` /
`actor_assign` and action names, and a context's CRUD function overrides
(`list_function`, `list_function_paginated`, `get_function`, `create_function`, ...):

```elixir
# Before
auix_resource_metadata :post, ash_resource: Post, ash_actor_assign: :current_user

# After
auix_resource_metadata :post, ash_resource: Post, backend_opts: [ash_actor_assign: :current_user]
```

They are validated by the resource's backend, so an Ash option on an Ecto resource fails
compilation.

**3. A field's `order_by` and `where` go under `query_opts`:**

```elixir
# Before
field :category_id, option_label: :name, order_by: [desc: :name], where: [{:active, true}]

# After
field :category_id, option_label: :name,
  query_opts: [order_by: [desc: :name], where: [{:active, true}]]
```

**4. Renderer settings go under `renderer_opts`:**

```elixir
# Before
field :cost, renderer: :rating, data: %{max: 10}

# After
field :cost, renderer: :rating, renderer_opts: [max: 10]
```

**5. Uploads are an `upload` block:**

```elixir
# Before
field :image, data: %{upload: %{allow: [accept: ~w(.png)], consume: &MyApp.store/1}}

# After
field :image do
  upload allow: [accept: ~w(.png)], consume: &MyApp.store/1
end
```

**6. `data` only accepts `select`.** The rest of `data` is filled by the backend parser. To
replace a select's choices: `data: %{select: %{opts: [Active: "active", Archived: "archived"]}}`.

**7. Options that were silently ignored now fail.** For example `max_length:` was never a
field option; use `length:`. A context resource without `context` also fails compilation.

**8. A module can hold only one Spark DSL.** An Ash domain (`use Ash.Domain`) or resource can't
also `use Aurora.Uix`; declare the UI in a separate module.

**9. `use Aurora.Uix.Layout.ResourceMetadata` is removed.** A module that only holds shared
metadata uses `use Aurora.Uix`. A view still reads it through `@auix_resource_metadata`, a map of
resources by name:

```elixir
# Before
defmodule MyAppWeb.Metadata.Product do
  use Aurora.Uix.Layout.ResourceMetadata

  auix_resource_metadata :product_admin, context: Inventory, schema: Product
end

# After
defmodule MyAppWeb.Metadata.Product do
  use Aurora.Uix

  auix_resource_metadata :product_admin, context: Inventory, schema: Product
end

# In the view, unchanged
@auix_resource_metadata %{product_admin: MyAppWeb.Metadata.Product.auix_resource(:product_admin)}
```

### Layouts

`auix_create_ui`, `auix_create_layout` and the layout calls (`index_columns`, `edit_layout`,
`show_layout`, `inline`, `stacked`, `group`, `sections`, `section`) keep their names and
arguments. Most layouts compile unchanged. These cases change:

**1. Layouts are validated.** `auix_create_ui`, `auix_create_layout` and every layout are now part
of the Spark DSL (`Aurora.Uix.Layout.CreateUI`). These cases used to be ignored or merged, and
now they fail compilation at their line:

- An unknown layout option or field option, or a layout option value of the wrong type, such as
  `pagination_items_per_page: "40"`. The type each option accepts is listed in
  `Aurora.Uix.Layout.Options.Index`, `Form` and `Show`.
  - `or_where:` and `select:` on `index_columns` were never applied to the index query, so remove
    them. The index has no replacement for `or_where`.
- A layout for a resource the module does not declare, or a field the resource does not have.
- Two layouts of the same type for one resource in one `auix_create_ui`. They used to merge;
  declare the layout once.
- A `section` outside `sections`, or a second `auix_create_ui` in a module.

**2. A field list made only of `key: options` pairs is read as options.** Spark reads such a
list as the sub-layout's own options. Write those fields with the new `field`:

```elixir
# Before
inline [id: [hidden: true], reference: [readonly: true]]

# After
inline do
  field :id, hidden: true
  field :reference, readonly: true
end
```

A list that also holds a plain field still works. Elixir only accepts `key: options` pairs at
the end of a list, so to keep a field with options before a plain field, write it as a tuple:

```elixir
inline [{:reference, [readonly: true]}, :name]
```

The same holds for a list made only of association paths (`inline [{:category_id, :name}]`).
Write each one as `field {:category_id, :name}`, or add a plain field to the list.
`edit_layout` and `show_layout` with options and no block fail the same way, so add the block:
`edit_layout :product, new_title: "New" do ... end`.

**3. `auix_create_ui` takes only `for`, `renderers`, `default_fields_layout` and the new `include`.** Name, title and
backend function overrides belong to `auix_resource_metadata`. Without a block, `for:` is not
accepted: write `auix_create_ui for: :product do end`.

**4. `auix_create_layout` takes no options.** Remove `omit_missing_layouts_creation?:`, which
never had an effect. A module that holds only `auix_create_layout` blocks can now be shared:
`auix_create_ui include: MyAppWeb.ProductLayouts` uses its layouts (see
[Reusable Layouts](../core/layouts.md#reusable-layouts)).

**5. `@auix_layout_opts` and `@auix_layout_trees` are no longer read.** Pass the options to
`auix_create_ui`, and declare layouts with it instead of writing `%Aurora.Uix.TreePath{}`
structs by hand. The generated `auix_layout_trees/0` is now `auix_layouts/0`.

**6. `Aurora.Uix.Layout.Blueprint`, `Aurora.Uix.Layout.CreateLayout` and `Aurora.Uix.TreePath`
are removed.** `use Aurora.Uix` brings the whole DSL. Remove any `import` of these modules.

**7. Group and section ids follow their position.** They used to embed the compile time, for
example `auix-group-quantities-1a2b3c4d123`. Now they look like `auix-group-quantities-product-form-0`.
Update any CSS or JavaScript that matched the old ids.

### Themes

Only themes you wrote yourself need changes. Using a built-in theme through
`config :aurora_uix, theme_name:` needs nothing.

**1. Rules are declared with `rule`, and the parent theme with `include`.** Turn each
`def rule(:name)` clause into `rule :name, css`, and the delegating catch-all into `include`.
Remove `@impl true`, the `@spec rule(...)` lines and any `def rule(_), do: ""`:

```elixir
# Before
defmodule MyApp.Themes.Ocean do
  use Aurora.Uix.Templates.Theme, theme_name: :ocean

  alias Aurora.Uix.Templates.Basic.Themes.ThemeBase

  @impl true
  def rule(:root_colors) do
    """
    :root[data-theme-name="#{@theme_name}"] { --auix-color-bg-default: #E0F2FE; }
    """
  end

  @impl true
  def rule(rule), do: ThemeBase.rule(rule)
end

# After
defmodule MyApp.Themes.Ocean do
  use Aurora.Uix.Templates.Theme, theme_name: :ocean

  alias Aurora.Uix.Templates.Basic.Themes.ThemeBase

  rule :root_colors, """
  :root[data-theme-name="#{@theme_name}"] { --auix-color-bg-default: #E0F2FE; }
  """

  include ThemeBase
end
```

Write `include` last to keep your rules ahead of the included ones, as `def rule(rule)` did. A
theme declares each rule name once and has at most one `include`. Both mistakes fail compilation,
and so does a theme that still defines `def rule(...)` clauses.

**2. Rule CSS is built at compile time.** A rule can use `@theme_name`, module attributes and
functions of other modules. It can no longer call the theme's own functions. Move them to another
module, or turn their result into a module attribute:

```elixir
# Before
def rule(:root_colors), do: colors()
defp colors, do: "..."

# After
@colors "..."
rule :root_colors, @colors
```

**3. `import_rule/2` is unchanged, and is imported by `use Aurora.Uix.Templates.Theme`.** Drop
`import Aurora.Uix.Templates.ThemeHelper, only: [import_rule: 2]`. It copies a rule of the same
theme or of the included one.

**4. The `breakpoint/1` function of the base theme moved** to
`Aurora.Uix.Templates.Basic.Themes.Breakpoints.breakpoint/1`.

### Custom renderers and templates

These changes matter only for code that reads the structures Aurora UIX builds. See
[Layout Structures](../advanced/advanced_usage.md#layout-structures).

**1. Renderers and templates read layout nodes.** `@auix.layout_tree` is an
`Aurora.Uix.Layout.Node` struct instead of `%Aurora.Uix.TreePath{}`. Match on the struct
instead of `tag`, and read its keys instead of `name`, `config`, `opts` and `inner_elements`:

```elixir
# Before
def render(%{auix: %{layout_tree: %{tag: :group, config: config}}} = assigns), do: ...
# config[:title], layout_tree.inner_elements

# After
def render(%{auix: %{layout_tree: %Aurora.Uix.Layout.Node.Group{title: title}}} = assigns), do: ...
# layout_tree.children
```

A field node holds its resolved `%Aurora.Uix.Field{}` in `field`. A layout's options are in
`options`, and its `*_action` entries are in `actions`. A template's `generate_module/1` reads the
layout type from `parsed_opts.layout_type`.

**2. Field options have their own keys on `%Aurora.Uix.Field{}`.** `data` now holds only what
the backend parser produces (associations, embeds, `select`):

| 0.1.7 | 0.2.0 |
|---|---|
| `field.data.option_label` | `field.option_label` |
| `field.data[:order_by]`, `field.data[:where]` | `field.query_opts[:order_by]`, `field.query_opts[:where]` |
| `field.data[:expanded]` | `field.expanded` |
| `field.data.upload` (a map) | `field.upload`, an `Aurora.Uix.Field.Upload` struct with `allow`, `consume`, `download` and `downloadable?` |
| renderer settings in `field.data`, such as `field.data[:max]` | `field.renderer_opts[:max]` |

**3. Resource options have their own keys on `%Aurora.Uix.Resource{}`.** `opts` is gone. Read
`order_by`, `display_name`, `title` and `renderers` directly, and backend options from
`backend_opts`. `fields` is always a map of resolved `%Aurora.Uix.Field{}` by key. `inner_elements`
is gone: a resource holds no layout.

**4. Custom layout option sets declare their options.** A module registered in
`:layout_options_parsers` names its layout type in `use` and declares each option with its
`Spark.Options` type. Its `get_default/2` clauses keep the defaults but are no longer read to find
the options:

```elixir
# Before
use Aurora.Uix.Layout.Options, :index

# After
use Aurora.Uix.Layout.Options, layout_type: :index

option :my_option, {:or, [:string, {:fun, 1}]}
```

Layout values for the option are checked against its type. `available_options/0` is replaced by
`options/0`, which returns `Aurora.Uix.Layout.Options.Option` structs.

**5. `Aurora.Uix.Templates.Basic.Helpers.flatten_layout_tree/1,2` is removed.** It read
`inner_elements`. Walk a layout node's `children` instead:

```elixir
# Before
Helpers.flatten_layout_tree(layout_tree)

# After
defp flatten(%{children: children} = node), do: [node | Enum.flat_map(children, &flatten/1)]
defp flatten(node), do: [node]
```

**6. The 0.1.7 DSL internals in `Aurora.Uix.Layout.Helpers` are removed:** `create_layout/2`,
`create_layout_opts/1`, `extract_block_options/2`, `prepare_block/1`, `put_manual_opts/3`,
`put_manual_tree_paths/3` and `register_dsl_entry/6`. They built layouts from the old macros and
have no replacement. Declare layouts with `auix_create_ui` or `auix_create_layout`.

### Migration prompt

Copy the whole block into your coding assistant (Claude Code, Copilot, Cursor, ...) at the root of
your project. Every step is a rule with an exact replacement, or a report-only step: the
assistant writes what it found to a temporary report file and changes nothing. Read that report
afterwards: the cases it lists need your decision, and are covered above in
[Layouts](#layouts), [Themes](#themes) and [Custom renderers and templates](#custom-renderers-and-templates).

````text
You are migrating this Elixir project from aurora_uix 0.1.7 to 0.2.0. Follow the steps in order.
Do exactly what each step says. Do not improve, rename, reformat or refactor anything else. Do not
touch Ecto schemas, changesets, Ash resources/actions or contexts. If a step's pattern does not
match anything, skip it. If a step says REPORT, do not change the code: append one line
"<file>:<line> <step number> <the code>" to the report file (see step 0.2) and go on.
Reference (read-only, never needed to decide anything): https://hexdocs.pm/aurora_uix/0-2-0.html

STEP 0. Preparation
0.1 In mix.exs change the dependency to {:aurora_uix, "~> 0.2.0"}. Run `mix deps.update aurora_uix`.
0.2 Create an empty temporary file named MIGRATION_REPORT.md in your system's temporary location, outside the project directory (it must never be part of the project or committed). Call it "the report file" and remember its path.
0.3 "DSL modules" below means every .ex/.exs file under lib/ and test/ that contains `use Aurora.Uix`,
    `use Aurora.Uix.Layout.ResourceMetadata` or `use Aurora.Uix.Templates.Theme`.

STEP 1. use Aurora.Uix.Layout.ResourceMetadata
In every file, replace `use Aurora.Uix.Layout.ResourceMetadata` with `use Aurora.Uix`.

STEP 2. Remove imports of deleted modules
Delete every line `import Aurora.Uix.Layout.Blueprint`, `import Aurora.Uix.Layout.CreateLayout`,
`import Aurora.Uix.TreePath` (also their `alias` / `require` forms).
If any other reference to Aurora.Uix.Layout.Blueprint, Aurora.Uix.Layout.CreateLayout or
Aurora.Uix.TreePath remains (including `%Aurora.Uix.TreePath{`), REPORT it.

STEP 3. auix_resource_metadata: keyword options together with a `do` block
For every `auix_resource_metadata <name>, <kw options> do ... end`:
turn each keyword option into a call on its own line inside the block, before the first `field`,
in the original order: `key: value` becomes `key value`.
Example:  `auix_resource_metadata :product, context: Inventory, schema: Product do`
becomes   `auix_resource_metadata :product do` + lines `context Inventory` and `schema Product`.
Calls without a `do` block keep their keyword options unchanged.
Apply step 4 to the options first when both apply.

STEP 4. auix_resource_metadata: backend options
In every auix_resource_metadata (keyword form or block form), move each of these options into
`backend_opts: [ ... ]` (block form: `backend_opts [ ... ]`), keeping key and value:
ash_actor_assign, actor_assign, list_function, list_function_paginated, get_function,
delete_function, create_function, update_function, change_function, new_function,
ash_read_action, ash_read_action_paginated, ash_get_action, ash_destroy_action, ash_create_action,
ash_update_action, ash_change_action, ash_new_function.
All of them go into one single backend_opts list. Options not in this list stay where they are.

STEP 5. field options
In every `field`, `fields` and every layout field written as `field :x, ...`:
5.1 `order_by: V` and `where: V` become `query_opts: [order_by: V, where: V]` (only the ones present;
    one single query_opts list per field).
5.2 `data: %{option_label: V}` becomes `option_label: V` and is removed from `data`.
5.3 `data: %{expanded: V}` becomes `expanded: V` and is removed from `data`.
5.4 Any other key K inside `data: %{...}` except `select`: it becomes `renderer_opts: [K: value]`
    (one single renderer_opts list per field; also when written `data: %{max: 10}`), and is removed
    from `data`.
5.5 `data: %{upload: %{allow: A, consume: C, download: D, downloadable?: X}}` (only the keys present)
    is removed from the field and the field becomes a block:
        field :x do
          upload allow: A, consume: C, download: D, downloadable?: X
        end
    Keep the field's other options on the `field :x, other: options do` line.
5.6 If `data` ends up empty (`data: %{}`) delete it. `data: %{select: ...}` stays unchanged.
5.7 `max_length: V` becomes `length: V`.

STEP 6. Options that 0.1.7 ignored
Run `mix compile`. For each error "unknown options" / "unknown key" that names an option in a
`field`, `auix_resource_metadata`, `auix_create_ui`, `auix_create_layout` or layout line (including
`or_where:` and `select:` in `index_columns`): delete exactly that option, and REPORT it
(step number 6, with the deleted option). Repeat until there are no more such errors.

STEP 7. auix_create_ui and auix_create_layout
7.1 In `auix_create_ui`, delete every option other than `for`, `renderers`, `default_fields_layout`,
    `include`, and REPORT each deleted option.
7.2 `auix_create_ui for: :name` without `do ... end` becomes `auix_create_ui for: :name do end`.
7.3 In `auix_create_layout`, delete the option `omit_missing_layouts_creation?: ...`.
7.4 Module attributes `@auix_layout_opts` and `@auix_layout_trees`: REPORT each, change nothing.
7.5 Calls to `auix_layout_trees()` / `auix_layout_trees/0` become `auix_layouts()`.

STEP 8. Layout field lists made only of `key: options`
For every layout call (`inline`, `stacked`, `group`, `sections`, `section`, `index_columns`,
`edit_layout`, `show_layout`) written as `name [ ... ]` where every element is `key: options`:
8.1 `inline [id: [hidden: true], reference: [readonly: true]]` becomes
        inline do
          field :id, hidden: true
          field :reference, readonly: true
        end
8.2 A list that also contains a plain atom stays as it is; each `key: options` that precedes a
    plain atom is rewritten as a tuple `{:key, options}`.
8.3 A list made only of association tuples `[{:category_id, :name}]` becomes a block with one
    `field {:category_id, :name}` per element.
8.4 `edit_layout :name, <options>` or `show_layout :name, <options>` without `do ... end` gets
    `do end` appended.

STEP 9. Group and section ids
Search the lib, test and assets directories for the text pattern `auix-(group|section)-[a-z_]+-[0-9]{5,}`. REPORT each hit.
(New ids look like `auix-group-quantities-product-form-0`.)

STEP 10. Themes (modules containing `use Aurora.Uix.Templates.Theme`)
10.1 Every `def rule(:name) do <css> end` / `def rule(:name), do: <css>` becomes `rule :name, <css>`.
10.2 The clause `def rule(rule), do: X.rule(rule)` becomes `include X`, written after all `rule` lines.
10.3 Delete `@impl true` lines directly above former rule clauses, every `@spec rule(...)` line, and
     `def rule(_), do: ""`.
10.4 Delete the line `import Aurora.Uix.Templates.ThemeHelper, only: [import_rule: 2]`.
10.5 If a rule body calls a function defined in the same theme module, REPORT it, change nothing.
10.6 Replace `Aurora.Uix.Templates.Basic.Themes.Base.breakpoint(` with
     `Aurora.Uix.Templates.Basic.Themes.Breakpoints.breakpoint(` (and the alias form `Base.breakpoint(`
     only where `Base` aliases `Aurora.Uix.Templates.Basic.Themes.Base`).

STEP 11. Custom layout option sets (modules registered in `:layout_options_parsers`)
Replace `use Aurora.Uix.Layout.Options, :index` with `use Aurora.Uix.Layout.Options, layout_type: :index`
(same for :form and :show). Then REPORT the module (declaring each option with `option name, type`
needs a human decision), and change nothing else.

STEP 12. Custom renderers and templates
REPORT every occurrence of each of these strings in the lib and test directories (change nothing):
`layout_tree`, `inner_elements`, `flatten_layout_tree`, `.data.option_label`, `.data[:order_by]`,
`.data[:where]`, `.data[:expanded]`, `.data.upload`, `.opts`, `parsed_opts`, `create_layout_opts`,
`extract_block_options`, `prepare_block`, `put_manual_opts`, `put_manual_tree_paths`,
`register_dsl_entry`, `Layout.Helpers.create_layout`.

STEP 13. Modules with two Spark DSLs
REPORT every file that contains both `use Aurora.Uix` and one of `use Ash.Domain`, `use Ash.Resource`.

STEP 14. Verify
Run, in this order, and stop at the first one that fails:
`mix format`, `mix compile --warnings-as-errors`, `mix test`.
If `mix compile` prints an error for a line you did not change, copy the error into the report file under "COMPILE ERRORS" and stop. Do not fix it.
Finish by printing the content of the report file and its path.
````
